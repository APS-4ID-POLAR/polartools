polartools.image_viewer#

A 2D image-stack viewer for the detector files that accompany a master file.

MyNXWriter puts the scan’s scalar channels in *_master.hdf but leaves the area-detector frames out of it – .../streams/primary/lambda250k carries only EPOCH/time and no value. The pixels are written separately, by one of two writers, and the master records which one and where.

The pvapy streaming consumer writes a sibling file, named in entry/instrument/bluesky/metadata/pva_streaming:

file_name: pva_tise2_2_00006.h5
file_path: ~/6idb-bits/sarah_26_3_2

An areaDetector plugin instead writes one file per detector into a subdirectory of the master’s own, listed in entry/instrument/bluesky/metadata/detectors_file_relative_path:

eiger: eiger/scan_000310.h5

– or the literal {} when the scan wrote no frames at all. Both are resolved against the master’s own directory: pva_streaming’s file_path and the companion detectors_file_full_path name the filesystem the scan was taken on, which a copy of the data is not. image_path_for_master() falls back to deriving pva_<stem without "_master">.h5 when neither is recorded, and opens the first detector where a master names several.

The image file’s layout. The pvapy writer produces all of this:

entry/data/data                (N, nx, ny)  the stack; ``pixel_order='xy'``,
                               i.e. ``frame[x, y]`` -- the same convention as
                               pyqtgraph's default col-major ImageItem
entry/data/frame_timestamp     (N,)         epoch seconds
entry/data/rois/<name>         (N, w, h)    pre-baked ROIs; the rectangle is in
                               the ``x``/``y``/``w``/``h`` attributes
entry/data/metadata/ca/<pv>    (N,)         one value per frame (eta, delta, cap, ...)

An areaDetector file carries the stack and nothing else from that list – no stored ROIs, no frame_timestamp – but it does bring its own per-frame attributes, which are read in the same way as the CA metadata above:

entry/instrument/NDAttributes/NDArrayEpicsTSSec   (N,)  the frame clock,
entry/instrument/NDAttributes/NDArrayEpicsTSnSec  (N,)  counted from 1990
entry/instrument/NDAttributes/<name>              (N,)  BeamCenterX, ...

Its frames are stored [frame, x, y] too, despite declaring no pixel_order: on an EIGER2 X 1M the 38-pixel module gap falls across the second frame axis, splitting it 512/38/512, so that axis is the detector’s height and the first is its width. Nothing needs transposing to display.

The frame count need not match the master scan’s point count (the detector usually starts a little early), so this window is deliberately self-contained: every per-frame quantity it plots comes from the image file itself.

entry/data/data is compressed with a filter hdf5plugin registers (blosc from the pvapy writer, bitshuffle from areaDetector), so that package must be importable. It is imported here if present; if it is not and the pixel read fails, ImageData raises a RuntimeError naming it.

Where the matching *_master.hdf can be found – beside the image file, or one directory up when the frames sit in a per-detector subdirectory – its primary stream is offered too, under a scan/ prefix, each frame taking the scan point nearest it in time, since the detector free-runs and the two files rarely have the same number of points.

Both ROI plots can normalize by any of the same quantities their axes offer (a CA channel such as a monitor, or another ROI metric): the value axes are divided by it point by point, after any background subtraction.

Any ROI can be marked as the background: its mean intensity per pixel is then subtracted from every other ROI’s sum (as background x pixel count) and from their mean/min/max, per frame and per file.

An HKL 3D button maps the frames into reciprocal space, taking the geometry from the matching master file (see hkl_viewer.py); it needs pyvista and xrayutilities, and says so plainly when they are absent.

Several files can be opened at once: they are shown side by side in one window, sharing a single set of ROIs, one colour scale and one frame control, so scans can be compared directly. The frame control spans the longest file; a file that has run out of frames keeps showing its last one.

Run standalone on one or more image files with:

python image_viewer.py scan_000310.h5 [scan_000311.h5 ...]

polartools.image_viewer.recorded_detector_file(master: pathlib.Path, detector: str | None = None) → str | None#

The file master records for detector, exactly as written.

The one line of the detectors_file_relative_path block that detector labels – "vortex" picks vortex: vortex/scan_000055.h5 – or the first line’s value when detector is None.

Public, and by name rather than by position, for spectrum_viewer: that module wants one detector’s line out of a master that may list several, where _recorded_image_paths() wants every source in the order worth opening and takes the first line when a block is unlabelled. Reaching across for _block_value() and _decode() instead would make their underscores a lie, and hand-parsing the block a second time in another file would duplicate exactly the {} and truncated-eiger: reasoning those two were written down once to settle.

What comes back is a claim, not a path that exists: see spectrum_path_for_master() for how far it can be trusted.

polartools.image_viewer.image_path_for_master(master: pathlib.Path) → pathlib.Path | None#

The image file belonging to master, or None if none was found.

Prefers what the writer recorded – a pvapy sibling, or an areaDetector file in a per-detector subdirectory – and falls back to the <master stem minus "_master"> -> pva_<stem>.h5 convention. Everything is resolved against the master’s own directory, so that a copy of the data opens its own frames rather than the originals it was copied from. Where a master names several detectors, the first is the one opened.

polartools.image_viewer.master_path_for_image(image: pathlib.Path) → pathlib.Path | None#

The master file this image file belongs to, beside it or one level up.

An areaDetector writer puts the frames in a per-detector subdirectory of the master’s own, so <dir>/eiger/scan_000310.h5 belongs to <dir>/scan_000310_master.hdf. The image’s own directory is searched first, so a pvapy sibling still pairs with the master beside it.

Looking a level up can in principle pair a stray file with a master that merely shares its stem; the time-overlap check in read_scan_channels() is what rejects those.

polartools.image_viewer.read_scan_channels(image: pathlib.Path, frame_epoch, n_frames: int | None = None) → dict[str, numpy.ndarray]#

The master file’s primary fields, resampled onto the image’s frames.

The detector free-runs, so the two files rarely have the same number of points – 103 frames against 101 scan points is typical, the camera starting a moment early. Each frame therefore takes the value of the scan point nearest it in time; frames outside the scan hold the first or last point.

When the image file carries no per-frame timestamp at all, there is no clock to match against, so frames are instead spread evenly across the master’s scan points by position (see _evenly_spaced_index) – a rougher alignment, but the best available without a time base.

class polartools.image_viewer.ImageData(path: pathlib.Path)#

The whole contents of one detector image file, held in memory.

stack is (n_frames, nx, ny) float32 – indexed [frame, x, y], the pvapy writer’s declared pixel_order='xy' convention and, as the module docstring works out from where the module gap falls, areaDetector’s layout here as well. That is also what pyqtgraph’s default (col-major) ImageItem expects, so frames need no transposing to display the right way round.
